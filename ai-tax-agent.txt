## One important addition I'd make

Because you're using Terraform, I want Copilot to maintain **two distinct boundaries**:

```text
APPLICATION CODE
app/
├── FastAPI
├── Agent
├── RAG
├── Tools
├── LLM
└── DB

INFRASTRUCTURE
infra/
└── terraform/
    ├── modules/
    └── environments/
```

Don't let Copilot start putting AWS provisioning logic inside Python. Your Python application **uses** AWS; Terraform **creates/configures** AWS infrastructure.

The eventual flow should be:

```text
                  Git Repository
                       │
          ┌────────────┴────────────┐
          │                         │
          ▼                         ▼
    Application Code           Terraform
          │                         │
          ▼                         ▼
      Docker Image              AWS APIs
          │                         │
          ▼                         ▼
         ECR                    AWS Infra
          │                         │
          └────────────┬────────────┘
                       ▼
                   ECS/Fargate
                       │
          ┌────────────┼─────────────┐
          ▼            ▼             ▼
       Bedrock        RDS            S3
          │
          ▼
      AI Tax Agent
          │
          ▼
       Qdrant
```

### And one thing I would **not** let Copilot do

Don't give it permission to execute:

without you reviewing the plan.

The workflow should always be:

```bash
terraform fmt -recursive

```

**You inspect the plan → then `terraform apply`.**
